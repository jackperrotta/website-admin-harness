# Stable npm releases

The public package family is @tryvitris/website-admin-harness, @tryvitris/create-website-admin-harness and @tryvitris/website-admin-contracts. Version 1.0.0 is the first stable release, with synchronized versions, public access and the latest tag. Node.js 24+ is required. The initializer pins the exact runtime version.

Freeze and review all intended source changes before release. Use an isolated checkout and an isolated neighboring website source/dependency tree for paired acceptance, so another build cannot clean package outputs during verification. Run npm run release:pack to build, typecheck, run all tests including external package installation, audit actual archives, and save tarballs plus integrity hashes under artifacts/releases/VERSION. If the same frozen source already passed npm run check, the pack script can run directly without repeating the full suite.

Run npm run release:verify-packed against those saved archives. It validates each hash and uses the existing external-installation acceptance test with the exact tarballs, rather than repacking source. Review the privacy scan, package list, changelog and clean source state. Keep business credentials, configs, provider records and deployment receipts in each installation's ignored private directory and private Cloudflare secrets.

Publish the verified source to GitHub. Then run npm run release:publish in an interactive terminal. npm may require browser or one-time verification for each package; complete it directly in npm's trusted interface. Never put authentication codes or tokens in source, saved command arguments, logs or chat.

The publisher verifies every archive before the first upload, publishes contracts/runtime/initializer in order, and compares registry integrity against the reviewed bytes. Accepted uploads may take several minutes to become readable. publication-progress.json records each accepted upload immediately and checks for up to 15 minutes without re-uploading. Retrying resumes verification, skips already published matching versions and rejects conflicting bytes. publication-receipt.json is written after all three registry checks pass. Never publish different content under the same version.

After publication, run npm run release:verify. It checks registry integrity and latest tags, uses a fresh cache and empty npm credentials outside the workspace, runs npm create/install from the public registry, builds the Worker, applies only local migrations, exercises guarded website setup, and verifies authenticated/local-demo APIs. It writes registry-install-verification.json. Create the vVERSION Git tag and GitHub release after registry verification.

Version 1.0.0 includes billing, account lifecycle, client dashboard/onboarding previews, lead follow-up, analytics/interface improvements and optional scheduling/calendar/email workflows. Preserve their explicit opt-in, sender, test-mode and real-account acceptance requirements. Publishing packages does not upgrade or deploy customer installations, apply remote migrations, copy secrets, enable notifications, activate live booking or collect live payments. See CHANGELOG.md and the packaged agent workflow for reviewed installation upgrades.

Retain the patched Miniflare dependency overrides and check the dependency audit before publication. Keep exact source/commit identities, archive hashes, checks and registry receipts together as local release evidence.
