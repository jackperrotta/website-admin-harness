# npm alpha release

The public package family is @tryvitris/website-admin-harness, @tryvitris/create-website-admin-harness and @tryvitris/website-admin-contracts. Versions are synchronized; the current candidate is 0.1.0-alpha.2, with public access and the alpha tag. Node.js 24+ is required.

Run npm run release:pack to build, typecheck, run all tests including installation from external tarballs, audit package contents, and save reviewed tarballs plus integrity hashes to artifacts/releases/VERSION.

Run node --experimental-strip-types scripts/publish-release.ts --dry-run to inspect the exact reviewed release without publishing. Then run npm run release:publish in an interactive terminal. npm may prompt for two-factor authentication for each package; enter codes directly in that terminal. Never put authenticator codes or npm tokens in source, command arguments saved to files, or chat.

The publisher verifies every archive before publishing, publishes contracts/runtime/initializer in order, and compares registry integrity with the reviewed archive after each publication. npm may accept an upload with HTTP 202 while processing it for several minutes. Accepted uploads are recorded immediately in publication-progress.json, then checked for up to 15 minutes without re-uploading. Re-running the publisher resumes those checks. It skips already published matching versions on retry and refuses conflicting bytes. It writes publication-receipt.json only after all three registry verifications pass. Do not republish different content under the same version.

After publication, run npm run release:verify. It checks all registry integrity hashes and alpha tags, uses a new cache and empty npm credentials outside this workspace, runs npm create and npm install from the public registry, builds the Worker, applies local migrations, exercises guarded website setup, and verifies protected/local-demo APIs. It writes registry-install-verification.json. Tag the Git release only after publication and registry-install verification. Customer deployments and automatic npm latest promotion are separate operations.

The alpha.2 candidate adds scheduling, calendar synchronization, public booking, customer emails/links and reminders, plus admin analytics/theme support and maintained TypeScript entry points. Scheduling remains opt-in and test-only. Real Google/Microsoft OAuth apps, email sender onboarding, challenge execution, cron and reviewed migrations through 0008 are installation steps. Local fixtures do not establish live provider or inbox acceptance. Development installs preserve patched Miniflare dependency overrides for Undici 7.30.1 and Sharp 0.35.5; verify a clean dependency audit before publishing.
