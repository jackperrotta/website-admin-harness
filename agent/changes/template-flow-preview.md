# Preview onboarding before assigning a prospect

Add Preview client flow to every saved and starter template. Open an owner-authorized full-page route in the optional client-onboarding module, reuse the actual client journey components, and allow welcome, business, website, account, optional payment and completion inspection. Provide desktop/phone widths, jump-to-step, sample answers, reset, and a clear return to the template library.

The preview is a browser-memory simulation. Only the existing authenticated workspace GET loads template definitions. No prospect, invitation, account, draft, cookie, credential, email or payment operation may be created by preview controls. Password entry stays disabled. Real prospect signup retains its existing request handlers and protections. Missing/archived templates show an unavailable state. Disabled modules and unauthorized roles must not load the preview.

No backend routes, permissions, migrations, new services or production deployment are needed. Preserve existing local records and keep the preview process running. Verify actual shared stages and no network writes, starter/saved templates, optional-step omission, sample/reset state, mobile layout and access gates. Run npm run check, including packed installation, and show the result in the browser.

## Implemented behavior

Starter and saved cards open the owner-authorized `#client-onboarding?preview=TEMPLATE_ID` route. The preview uses the same signup, payment, and completion components as assigned clients, with explicit in-memory callbacks instead of API mutations. Only an authenticated workspace GET reads template definitions. Password fields are disabled. Preview step navigation, sample answers, reset and Desktop/Phone width controls stay in memory; return navigation restores the template library. Missing/archived IDs have an unavailable state, while disabled or unauthorized installations never load the preview.
