# Agent package maintenance

Add a shared typed update contract and Node-only discovery/plan SDK for the website harness and three admin packages. Read only exact installed/declaration/lock evidence and the public npm stable release family; distinguish unavailable, inconsistent, prerelease, local overrides, missing evidence and major updates. Do not execute remote instructions or install package lifecycle scripts.

Ship agent instructions and an idempotent existing-installation setup command. The policy is prepare/test compatible updates and follow the installation's existing publication permissions. Do not turn check/plan into an install, migration, deployment, key rotation, account change or schedule activation. The initializer inherits runtime scaffolding; the contracts package exposes and documents the same policy.

Connect website care to this SDK through a checked package-inventory command and identity-bound optional separate admin directory. Refresh its generated daily brief each run and reuse the current coordinator/schedule. Native schedule creation/read-back remains external; files never claim an active agent. Test packed packages outside these workspaces, wrong origins/identities, untrusted metadata, stable cohort mismatch and existing configuration preservation. No live customer rollout is part of this implementation.
