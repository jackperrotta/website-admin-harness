# Reusable onboarding templates and a full-page client journey

Extend only the explicitly enabled `client-onboarding` local variant. Owners can create, edit, duplicate, archive and apply reusable templates for different business categories. Templates store welcome copy, signup title/intro, question definitions, required flags, input kinds, question stages and whether payment setup is requested. They never store prospect answers. Applying creates a prospect-specific snapshot; edits/archive must not rewrite existing invitations. Retain per-client overrides and prefilled information.

Replace every customer signup/payment modal with a branded full-page mobile journey: preview first, business details, website goals, account creation, optional payment and completion. Show actual progress, back/continue controls, accessible validation and sensible phone keyboards. Save only non-secret draft answers server-side. A scoped HttpOnly invitation cookie permits refresh/resume without storing raw tokens or passwords in browser storage; expiry/replacement/revocation and one-use acceptance remain enforced. Do not add fake testimonials, urgency, charges or invented results. Payment remains an explicit simulation.

Add optional migration 0011 under the module's prototype migration directory for scoped template records and prospect config/draft snapshots. Owner-only existing prospects read/write permissions authorize all template actions; enforce revision checks and cross-installation IDs. Public callers only receive their assigned snapshot. Existing normal admins, staff auth, website connections and real billing remain unchanged.

Preserve the current local prospect and private live catalog. Move this preview to ignored persistent local D1 with a migration ledger and a stable private local password pepper, using a private snapshot of its existing local records for the one-time transition. Never migrate or deploy a remote database. Test template isolation/snapshot semantics, previous-schema migration, draft integrity/resume/expiry, required and typed fields, atomic account activation, disabled/unauthorized access, full customer flow and desktop/mobile layout. Run npm run check and packed external installation acceptance. Leave the working preview open for review.
